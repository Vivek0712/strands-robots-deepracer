# First Principles: the showcase is one claim, not a menu

"Which use cases" is the wrong question. It assumes the showcase is a menu, and "five pillars" is a vendor scorecard the audience never asked for. Strip it back.

**What is actually being solved.** A chat agent's mistakes are reversible; a motor's are not. "Physical AI" is therefore one claim: *an agent whose authority over the motor is enforced by construction, whose actions are verified against the world rather than asserted, and whose every stop can be explained.* An LLM calling `drive()` is none of those. That claim is the demo. The pillars are mechanisms that appear on screen while the claim is proven; they are not acts.

**Goals, honestly stated.** Audience: leave with a mental model they can code tomorrow (gate, verdict, audit, deadman). Builder: upstreamable artifacts (deadman node, DeepRacer driver, decider image support). Ecosystem: Strands as the control plane that makes an LLM safe to bolt to hardware.

**Demonstrate vs decorate.** Decorate: U03, U04A, U05, U09, U21, U06 (consent is good governance but is a chat feature), U10 (software abstraction, not physicality; twin version is a slide), U20 standalone, U24. Demonstrate: U15 (fail-closed is the physics of the claim; everything else is a lie without it), U17, U07, U13, U11/U12 merged, U02, U18, U22.

**Rebuilt shape.** Infrastructure first: deadman node, pen, screen contract. One stage arc, roughly eight minutes: U22 go/no-go, U17 hops and a person stops it, U07 explains it, U11 sign refused, U13 blindfold, U15 plug pulled, U18 calibration fix (live only if SSH under 15 s, else recorded and labelled). Booth: U01 all day, U17 pen on demand, U07 whenever a real stop happens. Decider is the spine, Bidi is PTT, Box is a log line inside U18, never its own beat. Cut the rest without regret.
