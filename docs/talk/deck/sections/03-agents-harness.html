Part 3 · Strands Agents

Strands Agents: model-driven, one loop

  • "A model-driven approach to building AI agents in just a few lines of code." The model decides; the SDK runs the loop.
  • Each pass: the model decides, tools run, results return. It repeats until the model answers without a tool call.
  • Any model: Amazon Bedrock by default; Anthropic, OpenAI, Gemini, Ollama swap in with one model=.
  • Python 1.61.1 (15 Oct 2026), TypeScript 1.21.0 (14 Oct), Apache-2.0, one monorepo: strands-agents/harness-sdk.
from strands import Agent, tool

@tool
def letter_counter(word: str, letter: str) -> int:
    """Count occurrences of a specific letter in a word."""
    return word.lower().count(letter.lower())

agent = Agent(tools=[letter_counter])
agent('How many letter R\'s are in the word "strawberry"?')

Audience knows what an agent is; this is only the vocabulary we reuse for the rest of the talk. The loop labels (Request, Model decides next step, Tools execute tool calls, Response, "Every pass adds to the conversation history") are the labels of the official agent-loop diagram. Stop reasons exist (end_turn, tool_use, cancelled, limit_turns...) and agent.cancel() stops the loop from outside: that is the hook we use for "Pull the Plug" later.

Part 3 · Why it fits a robot

Four things a robot needs, already in the SDK

  • Interventions. Typed decisions before each tool call, evaluated in order.
  • Hooks. BeforeToolCallEvent, AfterToolCallEvent, BeforeModelCallEvent: observe or change the loop at any point.
  • The command gate. strands-robots' _command_gate owns approval for every motion topic: a human "yes", or an explicit STRANDS_ROS2_COMMAND_ALLOW for headless runs.
  • Bidi voice with barge-in. BidiAgent keeps one connection to Nova Sonic; BidiBargeInEvent clears playback when the user talks over it.
tool call drive_deepracer(throttle=0.3, steer=-0.5)
before_tool_call: every handler votes, in order
PROCEEDAllow the operation to continue unchanged
GUIDECancel and provide feedback for the model to retry with
CONFIRMPause for human approval (before_tool_call only)
DENYBlock the operation; short-circuits remaining handlers

Say the safety line out loud here, first time in this section: physics stops the car; the decider explains. Interventions are an explanation layer we can trust to be well behaved (fail-closed with on_error="deny"), not the thing that keeps a wheel off a foot. A fifth action, Transform, modifies event content in place; it is not on the slide.

The four descriptions are the interventions page's action table, word for word ("Allow the operation to continue unchanged", "Block the operation. Short-circuits remaining handlers", "Cancel and provide feedback for the model to retry with", "Pause for human approval"); the "before_tool_call only" qualifier is from the page's lifecycle table, and Confirm uses the SDK's interrupt/resume. The command gate description is from our code deep-dive of strands-robots (report 01, section 1.4). Barge-in: the bidi overview says the user can "talk over the agent (barge in)"; the stream-events page says to clear buffered audio when BidiBargeInEvent arrives, which AudioIO.output() does automatically.

Part 3 · The Harness SDK

"An agent harness is the software around a model that turns it into an agent."

  • Strands Harness SDK: build one yourself, end to end. Strands harness: the assembled one; create_harness() returns a plain strands.Agent.
  • Sandboxes. Shell and file tools run through Agent(sandbox=...): DockerSandbox, SshSandbox, or your own PosixShellSandbox. No sandbox means the host.
  • Policies. interventions="ask", "smart", a natural-language rubric, a .cedar file, or a handler such as CedarAuthorization. Subagents inherit it.
  • Memory. Sessions resume by id; long-term memory is markdown under ./.agent/memory.
  • Same loop as the agent loop, plus batteries: tuned prompt, context management, caching, subagents, skills.
official diagram, strandsagents.com (sandbox-execution-boundary.svg), recoloured to the deck tokens
from strands.sandbox.ssh import SshSandbox
from strands.vended_interventions.cedar import CedarAuthorization
from strands_harness import create_harness
agent = create_harness(
    instructions=INSTRUCTIONS,
    builtin_tools=["shell", "read", "write", "edit", "web_fetch"],
    interventions=CedarAuthorization(policies=POLICY, on_error="deny"),
    memory=True, session=True,
    sandbox=SshSandbox(host="deepracer@<car>", working_dir="/opt/aws/deepracer"),
)
ops/race_engineer.py, trimmed: the whole race engineer is this one call

The title is the first sentence of the SDK overview page; the first bullet's opening is its second sentence. Strands harness (the product) sits on the Strands Harness SDK (the toolkit); the docs say to use the harness when its defaults fit and the SDK directly for a bespoke tool set or a custom loop.

Sandbox facts from the "Available Sandboxes" page: both backends register sandbox shell and file-editor tools; SshSandbox spawns a fresh ssh process per command, key-based auth only, BatchMode enforced, an allowlist of ssh options. The sandbox overview says omitting the sandbox parameter runs the command and file tools directly on the host. PosixShellSandbox is the abstract base exported by strands.sandbox (package docstring in strands-py). The harness README says the environment plugin reads through the agent's sandbox "whether the agent runs locally, in Docker, or over SSH"; sandbox itself reaches Agent through **agent_kwargs (harness-py agent.py). Interventions sugar (ask, smart, rubric, .cedar, a handler, or a list) and memory are from the harness README sections "Requiring approval for tool calls" and "Long-term memory"; the README also says programmatic_tool_caller calls are gated, so delegation cannot bypass the policy. The code is our ops/race_engineer.py with the host resolution and env loading removed.

Part 3 · Harness tour

What create_harness() wires up

Sandbox

Shell and file tools run through the sandbox: host, Docker or SSH.

Policy

Cedar policies evaluated before each tool call: default-deny, fail-closed with on_error="deny".

Memory

Sessions resume by id; long-term memory as markdown files, plus search_memory.

Tools

Eight built-ins: shell, read, write, edit, web_fetch, web_search, programmatic_tool_caller, subagent.

Interventions

"ask" approves every call, "smart" adds an LLM risk classifier, a .cedar path loads a policy. Children inherit it.

Observability

OpenTelemetry spans for model, tools and subagents; off unless OTEL_TRACES_EXPORTER is set.

Also in the box: a tuned system prompt, context management, prompt caching, Agent Skills, and the strands CLI.

One line per card, each from the docs: sandbox (Available Sandboxes page and the official sandbox-execution-boundary diagram's story line: only execution crosses the boundary; model calls, hooks and state stay on your side), policy (Cedar Authorization page: the action is the tool name, context.input its arguments, context.session what your enricher adds), memory (README "Long-term memory": facts distilled into markdown, folded back into context, flush before a short run ends), tools (configuration reference; yours and MCP servers add alongside; a list pins names, a mapping edits), interventions (README "Requiring approval for tool calls": subagent children and programmatic_tool_caller calls are gated too), observability (README "Tracing": "the model loop, tool calls, and subagent delegation all emit OpenTelemetry spans"; with OTEL_TRACES_EXPORTER unset "the harness touches telemetry not at all"). The two built-in plugins (todos, environment) are in the configuration reference.

The tuned prompt, per the README: explore before changing, confirm before anything irreversible, verify before calling a task done. If asked "why not just Agent + tools": the harness is the fastest route to a preconfigured agent; everything is a default, not a constraint, and the return value is a plain Agent.

Part 3 · The rule

The harness is the race engineer, never the driving loop

  • Driving stays on strands-robots' gated drive_* tools. Cedar forbids manual_drive, cmd_vel and servo_msg in any harness shell command, confirmed or not.
  • The race engineer has SSH hands on the car: reads are free; a calibration write or a service restart needs the operator's yes.
  • Pit Stop on the stand, 14 Oct 2026. Read calibration.json over SSH (steering mid 1450000), recalled 1456000, reported the 6000 offset without changing anything.
  • Operator not confirmed: the edit call was refused by Cedar; the engineer proposed the fix and waited. The file stayed 1450000.
  • Physics stops the car; the decider explains.
forbid(principal, action == Action::"shell", resource)
when { context.input.command like "*manual_drive*" || ... };
forbid(principal, action in [Action::"write", Action::"edit"], resource)
unless { context.session has operator_confirmed
         && context.session.operator_confirmed == true };

This is the project's own rule, stated in CLAUDE.md and in report 08: "The harness is not the driving loop. Driving stays on strands-robots' gated drive_* tools with the car's safety envelope. The harness is the race engineer." The Pit Stop beat is pre-recorded (council verdict, report 11): live SSH over hall Wi-Fi and a bad write are both unacceptable risks. The "6000" is in nanoseconds of servo PWM (the README calls it a 6000 ns offset; the prompt called it 6 PWM units).

Honesty points to say: the "remembered" 1456000 is the staged premise of the beat; it entered memory through the refused-write request, as a presenter seeds it before the show. The car's real steering centre is 1450000 and was not touched. The red line in the transcript is the model's own <thinking> block, shown as recorded; the denial itself came from Cedar before the tool ran. The confirmed path (DEEPRACER_OPERATOR_CONFIRMED=1, the edit allowed, the car drives straight) was left for the recording session with the operator at the keyboard. Fixes the run produced: SshSandbox takes bare Option=value strings, and the engineer's notebook actions (search_memory, retrieve_context, todo_write) are permitted without confirmation since they never touch the car.
